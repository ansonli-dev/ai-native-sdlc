## 1. 起点与推进规则

已完成的设计基础：

- Intent → Spec → Plan → 本地实施、验证、审查与交接的方法约定。
- [Playbook 九项缺口的设计处理](../../research/method/anthropic-playbook-gap-audit.md#resolved-coverage)，以及工程责任、质量优先、Colla/MR 收尾等已确认决定。
- 一轮候选工具调查及部分来源核验，汇总在[工具选型页](../tools/existing-tools-reuse-plan.md)和[研究索引](../../research/README.md)。

后续始终遵守：

1. **质量先于效率。** 满足既定质量要求、没有已知质量退化后，才比较速度和 token；人工审核和修正属于实际流程，计入投入。
2. **本地 MVP 在 A4 验收。** MR、Colla 自动收尾和插件分发分别验收，不倒过来成为本地完成的前置条件。
3. **先复用，再补缺口。** 已有工具、配置和模板足够时直接采用；自研项必须有实际案例说明缺口。
4. **按既有责任推进。** Agent 完成已授权的调查、整理和实施；BA 承担业务确认，工程负责人或其委托者承担工程采用，代码/发布负责人承担相应操作授权。已有有效依据直接复用。
5. **步骤完成要有结果。** 必要验证未通过时保持未完成；记录受阻范围，继续不依赖它的工作。时间或成本上限不降低质量要求。

本页是**本方案建设的行动清单**；业务项目仍由 Colla 管整体进度、Plan 管工程 Tasks。方法规则由原正文维护，工具结论回写工具选型页，实际执行证据保留在目标项目。这里保存状态与链接，不复制一套需求、任务或运行台账。

## 3. A1：统一候选比较与首轮实测名单

**目标：** 从已有调研收敛到值得实测的少量组合，并明确哪些能力直接沿用现状。

**输入与责任：** 读取[工具选型页](../tools/existing-tools-reuse-plan.md)、[研究索引](../../research/README.md)及[实现分工](../tools/sdd-capability-implementation-map.md)。Agent 整理证据；需要工程取舍时按已有工程负责人/委托依据处理。此步不依赖试点仓库已经提供。

- [x] 按知识调查、材料/代码读取、三产物组织、执行与审查、宿主、原生验证和环境准备归拢候选；保留现有工具与普通文件读取作为对照。
- [x] 在工具选型页统一比较：需求覆盖、来源/版本、质量证据、未知项、适配与维护成本、许可/成熟度、重复依赖及退出方式。
- [x] 只补查会影响入围判断的证据缺口；把上游能力声明、源码核验和本项目实测明确区分。
- [x] 给出少量入围候选或组合、沿用现状的类别、排除理由，以及每个待测问题对应的案例和判据。

**产出位置：** 更新[工具选型页](../tools/existing-tools-reuse-plan.md)的比较与入围结论；新的来源依据进入对应研究笔记。

**完成条件：** 每个首版必需能力都有“沿用 / 入围待测 / 当前缺口”的处理；未知项不会被当作已支持。入围仅代表进入试验，正式采用留待 A4。

**下一步：** A2。若候选都不能覆盖某项必需能力，记录具体缺口并比较既有人工流程，不为了凑齐组合提前自研。

## 4. A2：选定试点与质量基线

**目标：** 得到一个真实既有仓库、一项边界清晰的小变更，以及公平比较候选的条件。

**输入与责任：** A1 的待测名单；可访问的项目、业务材料和现有工具。BA 确认试点的业务范围；工程负责人明确工程范围与可用条件，Agent 核验环境及比较安排。

- [x] 定位一个可实际运行相关检查的仓库，选择有清楚预期行为的小变更，注明原始诉求、已有 BA 材料、负责人和范围。
- [x] 记录代码及工作区状态、已有修改、工具/模型配置、项目规则、真实检查入口、测试数据与必要环境；运行适合该变更的基线检查并解释既有失败。
- [x] 预先确定质量判据和人工参与方式，从[产品回归案例](ai-sdlc-plugin-roadmap.md#101-产品回归案例)选择适用项，覆盖正常交付、中断恢复、上游修订和必要权限边界。
- [x] 固定候选比较的输入及起点，安排可恢复的试验环境；记录步骤历时、等待、人工投入和模型用量的来源，无法取得的值标为未知。

**产出位置：** 工具选型页记录试点入口和比较安排；目标项目复用既有项目活动记录或 `docs/project/evidence/<activity-id>.md` 保存环境与基线证据，实际路径按项目映射。

**完成条件：** 案例可以执行，正确结果可以判断，候选差异可以解释，必要操作范围明确；尚未具备的真实外部条件有明确边界。

**下一步：** A3，并可开始 A5 的只读核验。项目或业务输入缺失时，只提出具体缺项；不把材料准备完毕写成实测完成。

### 6.2 下一步工作单：跨机 A4.1 / H1 与 A4.2 对照

**当前执行入口：** 按[正式验证方案](../superpowers/plans/2026-09-17-a4-context-validation.md)及[移交材料](../../validation/a4-context/README.md)开始；先固定目标机环境和试点输入。下列 H1 步骤保留为协议检查摘要；分组、语义用例、质量判定与记录格式以正式方案为准。

**要回答的问题：** 在拟使用的 Claude Code 与原版 Superpowers 组合中，能否准确识别两种 brainstorming 调用，并把上下文送到实际执行的 Agent？先取得真实协议，再实现业务注入逻辑。

**起点：** 已只读观察到 Claude Code `2.1.250`、终端 Node `v24.15.0`；Claude 中的 Superpowers 实际版本、事件支持、Skill 输入和命令名均未实测。本机 Codex 中的 Superpowers 包不能替代这些证据。

**2026-09-17 接续修正：** 本机实际试验版本为自动更新后的 Claude Code 2.1.273，已确认 Claude 侧 Superpowers 6.3.0 和真实命令展开字段；模型请求因撤销的 OAuth 凭据返回 401。用户决定在另一台机器完成 Claude 验证，不再处理本机登录；该机器须记录自己的版本并重新验证。详见[执行记录](/Users/yuan.li/Documents/projects/explicit-architecture/docs/project/evidence/ai-sdlc-a4-context-hooks.md)。

**执行边界：** 在隔离的临时项目/配置中做最小诊断试验，使用无业务修改要求的提示和可识别的短上下文标记。需要诊断脚本或临时注册时仅服务事件采集；保留原配置和退出办法，不改试点业务代码、不写回 Colla，不把全量上下文插件提前塞入 H1。

| 次序 | 具体动作 | 交回证据 |
| --- | --- | --- |
| 1 | 核对实际启动的 Claude Code、Superpowers 版本/命名空间、配置加载范围、Hook 可用设置与 Hook 进程运行时 | 环境与加载清单；未安装、未启用或策略限制分别记录 |
| 2 | 临时注册最小诊断 Hook，先验证脚本能启动并返回合法的短 `additionalContext` | 活动配置位置、退出/恢复方法、宿主诊断与投递记录 |
| 3 | 让 Agent 真正调用目标 `Skill`，采集 `PreToolUse` 的必要字段及上下文投递 | 脱敏原始样本、技能名字段、事件与调用对应关系；未发生 Skill 调用不计通过 |
| 4 | 在真实交互入口输入对应斜杠命令，采集展开事件 | 脱敏 `UserPromptExpansion` 样本、命令名/来源、投递记录；向普通 prompt 填入斜杠文字不能代替此路径 |
| 5 | 运行一次无关技能/命令对照，核对识别边界；确认诊断关闭后可恢复原流程 | 不误匹配的对照及恢复结果，不依赖未经验证的命名后缀 |
| 6 | 对照设计固定事件适配结论、matcher 与 fixture，列明未支持路径及 H2 是否可开始 | 一份协议结论，必要时修正文档中的适配假设；不将“模型看见标记”扩大为“已读知识” |

**产出位置（执行时创建）：** 在试点既有 `docs/project/evidence/` 中新增 `ai-sdlc-a4-context-hooks.md`，连续记录各检查点的结论和证据入口；本方法仓库 `.local/pilots/explicit-architecture/a4-context-hooks/h1/` 保存必要的脱敏事件样本、最小诊断脚本与配置、运行片段。验证后的最小 fixture 在 H2 纳入插件测试，避免正式代码依赖临时目录。旧机文件已经创建；新的可移交诊断器位于 `validation/a4-context/h1/`。目标机证据按正式方案独立保存，不依赖原机绝对路径或完整日志。

**正常进入 H2 的标准：** 两条真实路径均有可核对样本；能固定精确匹配和响应协议；投递确实到达执行上下文；无关调用对照和恢复通过。协议结论至少逐条说明“已支持、缺少条件、待验证”，不能只写总括的成功。

**若一条路径不支持：** 先区分版本、加载和适配原因，在受控环境修正后复测。确实受限则保留已通过路径的结果，标明尚未覆盖的路径和人工接续方式；H2 可继续独立实现和单路径试验，H1 不标为完整通过，不能宣称双入口可用。需要改变目标版本或支持范围时由工程负责人按已有责任处理，不静默缩减质量要求。

### 6.3 A4 的总体验收与分流

各检查点完成后，核对整体条件：

- 所选上下文方式的实际读取、约束采用有依据；如采用 Hook，注入和相对规则基线的增益另有证据；声明支持的调用方式均已覆盖。
- Intent/Spec/Plan 职责、正式状态、已有授权和关键决定的接受依据一致；原版默认冲突已经处理并验证。
- 本次必要代码与文档满足要求，检查/审查覆盖最终工作区及新增文件；本次必需的 OpenWiki 更新已完成，范围外的待维护事项另行记录。
- 一次中断恢复、一次上游修订及适用的失败/限制场景通过；有效测试未被静默削弱，问题未解决不因预算或轮数耗尽而完成。
- 工程负责人或其委托者基于实际质量、人工参与和未验证边界接受采用结论；质量达标后才评估速度和 token。

业务代码和正式 Plan、`evidence/verification.md`、`evidence/review.md` 沿用项目既有落点；采用结论回写工具选型页。Hook 证据不成为第二份业务进度台账。提交、MR、Colla 收尾不是 A4 完成条件。

若上下文接入有效而完整流程仍不满足要求，单独保留该接入方式的受限试用结论，A4 的本地闭环保持未完成；解决具体冲突后继续，不自动重开所有候选横评。A4 完成后进入 A7 的本地能力复用；A5 同时完成时可进入 A6。

## 7. A5：核验 Colla/MR 接入条件

**目标：** 把已确认的业务规则变成可实施的字段、版本、权限和事件映射。

**输入与责任：** A2 确定的项目；[Colla 衔接](../method/project-documentation-system.md#colla-mapping)、[MR 收尾规则](../method/sdd-spec-to-commit-workflow.md#mr-closeout)。Agent 优先查现有项目配置、平台说明和 MCP 可用能力，接口/权限归属由现有项目负责人提供或确认。

- [ ] 确定代码托管平台、MR 状态、真实合并版本、源/目标分支，以及事件通知或流水线入口；区分平台事件与本地 Git hook。
- [ ] 核验 Colla MCP 实际支持的查询、内容同步、状态更新、修订条件与结果查询；记录允许写入的字段、权限和错误返回。
- [ ] 建立 Intent 路径/版本、Plan 范围、MR 与 Colla 事项的关联，覆盖一项需求对应多个 MR；明确整体关闭还需要哪些项目验收条件。
- [ ] 核验重复/并发处理、部分写入恢复与分支条件删除能力；不能可靠自动处理的动作注明人工接续办法。用无副作用检查或已授权的测试对象验证接口，保留结果。

**产出位置：** 目标项目既有入口/集成配置中的映射、接入工作的 Spec/Plan 及实际核验记录；本页只链接其位置。

**完成条件：** 能说明何种事件触发、更新哪个对象、如何核对成功、重复或失败时如何恢复，以及哪些动作不能自动执行。未知接口能力不能写成已支持。

**下一步：** A4 和本步都完成后进入 A6。权限或平台能力不足只阻塞相关接入动作，不阻塞本地 MVP。

## 8. A6：实现并验证 MR 自动收尾

**目标：** 实际合并后正确更新 Colla/Intent，并在满足条件时清理源分支。

**输入与责任：** A4 的本地结果、A5 的映射和有效授权。Agent 实现与验证；工程负责人核对接入结果，合并仍遵守代码负责人批准要求。

- [ ] 复用平台事件/流水线与 Colla MCP，按已核验能力配置连接；只有现成配置不能满足已证实需求时补薄连接代码。
- [ ] 重新读取实际合并状态、版本与范围；对部分 MR 只更新分项进度，全部范围及必要验收满足后才关闭 Colla 和归档 Intent，保留正文与证据。
- [ ] 实现逐项结果核对、去重、并发协调和中断恢复；分支删除绑定核对过的版本，无法保证条件时保留分支交人工处理。
- [ ] 在测试对象/受控环境验证下表，再按已有授权走通一条真实收尾链；支持范围以实际结果为准。

| 必测场景 | 预期结果 |
| --- | --- |
| 审核批准但未合并、MR 关闭但未合并 | 不触发整体关闭或分支删除 |
| 一份 Intent 有多个 MR，只合并其中一个 | 只更新已完成范围，剩余范围仍可追踪 |
| 重复、乱序或多个 MR 并发事件 | 不重复创建事项/收尾，不因最后收到一条事件就认定全部完成 |
| Colla 写入失败、成功响应丢失或执行中断 | 核对真实状态，只重试未完成动作，保留待同步结果 |
| 分支检查后新增提交 | 条件不符时停止删除，保留新工作 |
| 合并后更新 Intent 的归档标记 | 保留原文和原路径，不重写合并历史，不重复关闭同一业务范围 |

**产出位置：** 目标项目的接入配置/必要代码、验证记录、原 MR/流水线/Colla 结果，以及 `evidence/delivery.md` 或项目既有交付记录。

**完成条件：** 已声明支持的路径有实际通过证据，失败和并发场景不会误关事项或丢失工作；人工接续边界明确。此步仅验收 MR 收尾，环境发布与生产恢复由 E1/E3 验收。

**下一步：** 将已验证连接纳入 A7；无法满足的动作保留受限范围，不扩大自动化授权。
