# A4：项目规则与阶段 Hook 对照验证方案

> **执行者交接：** 使用 `superpowers:executing-plans` 按检查点执行；本方案与所引用的设计一起移交。负责执行实验的会话与被测 brainstorming 会话分开。用户将在另一台已安装并登录 Claude Code 的机器执行。

**Goal：** 判断原版 Superpowers 配合简短项目规则是否已满足知识调查要求，以及增加阶段 Hook 是否带来可复现的质量增益。

**Architecture：** 两组共享同一份知识要求、资料与模型配置；B 组仅在 brainstorming 调用时再次投递相同要求。先核验宿主协议，再进行隔离的设计质量对照，最后作有范围的采用决定。

**Tech Stack：** 目标机器的 Claude Code、原版 Superpowers、Node.js 内置模块；Python 3 生成临时诊断配置；Markdown/JSON 记录。受控设计试验不需要 Java 构建环境。

**Spec：** [候选 Hook 设计](../../tools/project-context-hook-plugin-design.md)、[接入方式对照](../../../research/execution/claude-native-stage-controls.md#上下文接入方式对照)、[试验材料入口](../../../validation/a4-context/README.md)。本文维护验证方法；[路线图](../../roadmap/action-roadmap.md#a4)维护 A4 状态。

版本：1.0；日期：2026-09-17。状态：**正式执行方案及材料已准备，目标机器实测尚未执行。**

## 1. 范围与全局约束

- 工程负责人为用户；既有授权覆盖隔离调查、配置试验、文档和检查。最终采用结论由工程负责人或其明确委托者接受。
- 质量优先；速度、token 与维护成本仅在质量要求满足后比较。人工可以参与，首次结果与人工修正后的结果分别保留。
- 保持原版 Superpowers。先做项目级配置；插件打包、新 Skill、修改 brainstorming 均不是本轮前置。
- 本轮比较 **A：项目规则** 与 **B：项目规则＋Hook**；与 A3 的 OpenSpec / Spec Kit 两组无关，不重开工具横评。
- 受控材料只进入隔离副本。正式项目 Wiki/ADR、业务代码、用户配置、Colla/MR 均不因实验自动变更。
- 主实验止于 brainstorming 的设计草稿及必要澄清。通过本轮不代表 writing-plans、审查子代理、代码实施或整个 A4 已通过。
- 原机仅证明 Claude Code 2.1.273 / Superpowers 6.3.0 的手动命令展开命中及输出接受；API 401 阻止了成功模型轮次。诊断器 16 项本地测试不能替代目标机协议或语义验证。
- 目标机器可用版本不必强行降级到旧版本；记录版本并完成其自己的验证。同一比较批次固定 CLI、模型实际 ID、推理设置、Superpowers 内容、配置和材料版本。

## 2. 要回答的问题与分层证据

| 层次 | 问题 | 可接受证据 | 不能作为替代的证据 |
| --- | --- | --- | --- |
| E1：事件 | 正确入口是否触发了正确处理器？ | 实际宿主事件及精确技能/命令字段 | 人工构造 stdin、提示中出现斜杠文字 |
| E2：投递 | 补充内容是否进入下一次成功模型请求？ | 宿主投递记录及协议试验中的随机标记回显，标记不出现在用户 prompt | 处理器写出了 JSON、模型请求 401 |
| E3：读取 | 相关资料正文是否实际可见？ | 工具返回或已加载正文记录，包含文件与版本；在设计形成前发生 | 只有搜索命中、路径列表、自述“已阅读” |
| E4：采用 | 设计是否正确使用适用约束？ | 对照原文与源码的人工复核；错误资料被纠正、缺口被识别 | 输出出现 Wiki/ADR 字样、引用列表很长 |

E2 的标记回显是投递探针，不是知识理解证据。A 组没有阶段 Hook，E1 标作“不适用”，不能给 A 扣质量分。组间比较以 E3/E4 为主。

在目标机器创建三个相互分开的目录，路径由操作者选择：

```text
method/                         方法仓库或本次移交包；操作者阅读
pilot/                          explicit-architecture 的同版项目材料
a4-evaluation/
├── control/                    环境记录、评分表、完整提示、评审答案
├── frozen/                     固定的原始资料与各 case 快照；不作为会话 cwd
├── workspaces/<run-id>/         每次独立复制，只放该用例被测资料
└── results/<run-id>/            原始输出、必要日志、运行记录；在被测目录外
```

被测会话从自己的 `workspaces/<run-id>/` 启动，不添加 method/control/results 为可访问工作目录，不把本方案或评分答案放进它的 prompt。路径隔离用于控制实验污染，不宣称构成操作系统安全沙箱；若实际读到了评分答案或其他组产物，保留该轮并标作污染，重做匹配的一对。

完整移交包的 `pilot-inputs/` 已包含本轮所需的只读资料快照及来源/哈希记录，可直接用作受控比较的 frozen 起点；它是选择性摘取，不是完整可构建仓库。包内不含 Claude 登录凭据、原机用户配置或完整会话日志。后续 A4.6 仍需完整 pilot 项目，尤其 `openwiki/`、`docs/project/`、`AGENTS.md` 和现有 `CLAUDE.md` 有未提交内容，单纯 clone 原 HEAD 不足以恢复当前起点。若只搬方法文档，则按 cases.md 另行准备 pilot 输入。缺材料时可先完成 H1，语义对照保持“缺少输入”。

## 4. 分组与公平性

两组的实验工作区都保留同版项目权威材料，在根 `CLAUDE.md` 追加同一条 `@.ai/context-policy.md`，该文件逐字复制共用 `knowledge-policy.md`。根文件已有内容保持一致。

| 控制项 | A：项目规则 | B：项目规则＋Hook |
| --- | --- | --- |
| 原版 Superpowers、模型、工具和权限 | 相同 | 相同 |
| 项目规则及实验资料 | 相同 | 相同 |
| 常驻知识要求 | 启动时导入同一短文件 | 启动时导入同一短文件 |
| 新增阶段 Hook | 无本试验 Hook | 目标技能调用时再投递该短文件全文 |
| 产出和评审要求 | 相同 | 相同 |

这检验的是**额外阶段投递的实际价值**，其时机与重复强调同时变化；即使 B 更好，也不能单独归因于时机。B 不额外获得文档全文、专属约束、工具、人工提醒或更长的任务提示。若以后要比较“常驻完整要求”与“按需独占加载”，另立实验，不能把这次结果当作 token 节约证据。

逐轮冻结并记录：材料文件哈希、共同 policy 哈希、根 CLAUDE.md 哈希、Superpowers 版本及 skill 文件哈希、实际工具清单、插件/MCP/Hook 清单、模型设置、可见的用户/项目规则与自动记忆。`--setting-sources` 不应被假定能移除所有记忆/上级指令；核对实际加载来源。无法消除但两组相同的背景指令写入限制，包含答案的背景信息则构成污染。

## 7. Task 3：准备最小 B 组实现，检查对照有效性

**输入：** H1 已确认协议、共用 policy。**输出：** 目标机本次实验用注入脚本、单元测试、A/B 启动配置和文件差异清单。

**当前缺项：B 组语义注入脚本尚未实现。** 移交的 H1 脚本只返回诊断 marker，不能拿它直接评价知识采用。本任务在目标机完成；不要求先实现整个候选插件。

- [ ] 以候选设计第 5 节的响应协议实现 `control/inject-context.mjs`：stdin 为真实 Hook JSON；由固定启动配置传入该 run 的绝对项目根；仅识别 H1 确认的两个目标入口；从本 run 的 `.ai/context-policy.md` 读取全文并返回 `additionalContext`。
- [ ] 将项目根视为操作者配置，将事件输入视为数据。校验事件 cwd 属于该根、policy 实路径未越界；拒绝错仓库/错 worktree 的注入。不从 prompt、参数或配置执行命令。
- [ ] 正常匹配返回单个 JSON、exit 0；不匹配/关闭返回空 stdout；可捕获错误只写明确 stderr 并放行，不宣称成功。无权限决定、不调用网络/MCP/模型、不自动读 Wiki 全文；每次调用重新读取 policy，不做会话级去重。
- [ ] 实现有界输入与输出：stdin ≤1 MiB、policy UTF-8 文件 ≤32 KiB、最终文本 ≤6,000 Unicode 字符；超限、缺失及非法 JSON 均有明确诊断。本试验只支持操作者固定的单项目根，不宣称已经实现设计第 4 节完整项目发现和 schema。
- [ ] 用子进程测试验证：两入口逐字输出 policy；其他命名空间/后缀/技能不输出；malformed/超限输入；缺失/越界 policy；cwd 越界；关闭开关；同会话再次调用读取新 policy；无权限字段；错误不产生成功 JSON。先取得失败，再实现到通过。
- [ ] A/B 启动配置除本试验 Hook 注册及诊断标识外一致。保留原版 Hook；不以全局 `disableAllHooks` 创建 A 组。冻结脚本、配置及共同 policy 的哈希。
- [ ] 用 S1 每组每入口各做一次冒烟，共 4 次；只核对能启动、读文件、调用技能、保存证据。冒烟不进入主比较。冻结后主试验期间不按某组结果单独加强提示。

**通过条件：** 离线协议测试及 4 次冒烟有结果；B 的实际投递文本与 A 的常驻 policy 相同；唯一处理差异可解释。本任务完成支持开始对照，不等于 A4.2 已通过，更不等于完整生产注入器已完成。

## 8. Task 4：执行语义对照与边界用例

**输入：** 已冻结的四份 case、两组配置、统一提示。**输出：** 每轮原始输出、证据、首次及修正后评审结果。

### 8.1 主比较矩阵

四个用例见 `cases.md`：S1 正常资料；S2 过期 Wiki＋被替代 ADR；S3 缺少关键原文；S4 ADR 与上位架构约束冲突。

每个用例 × 两种入口（M 模型 Skill、U 手动斜杠）× 两次独立重复 × 两组 = **32 次有效运行**。同一用例/入口的第 1 次按 A→B，第 2 次按 B→A；每轮均使用全新目录与会话，固定材料，保留运行顺序。两次重复是小规模试点安排，不构成统计显著性或长期可靠性的证明。

- [ ] 提前登记 32 个 run-id，例如 `S2-M-r1-A`，复制 run 模板；记录开始时间及配置/材料哈希。
- [ ] 每轮从自己的工作区启动。主试验可用 Read/Glob/Grep/Skill 等读取工具；两组实际工具一致。提示限定产出对话中的设计草稿，业务文件不改动；工具限制及其对原版完整流程的影响写入边界。
- [ ] 按 `prompts.md` 投入完全相同的业务请求，入口只按 M/U 变换。M 未发生 Skill 调用则记录入口未达成，并单独报告频率，不能只挑选成功调用的样本。
- [ ] 遇到澄清按共用答复卡回答，逐字记录。不得提醒某组“你忘了查 ADR”。无卡可答的问题由操作者据实澄清；若提供了新的任务实质信息，则同步更新一对的输入并重跑，原结果保留。
- [ ] 在首次可审阅设计、明确阻塞结论或真实错误处保存原结果，再开始评分。S3 正确请求缺失原文可以通过该用例，不以强行产出完整设计作为成功。
- [ ] 评审者使用 `review-guide.md` 核对文件正文、调用记录和设计；遮去组名先评分内容，再核对技术证据。用户可承担评审，不把生成者自评当作独立质量结论。
- [ ] 如需修正，在冻结首次评分后提出相同标准的反馈；分别记录修正投入和最终状态。首次失败不会因为修正后通过而消失。

环境/API 错误标“不可评估”；知识遗漏、错误采用属于质量失败；读取答案属于污染。所有尝试都进入分母清单，失败不删除。有效运行不足则补足；没有时间继续就交接“未完成”，不能按预算结束推导通过。

### 8.2 恢复与故障检查

主比较后执行下表，每项保留独立记录，不混入 32 次质量比例。适用范围不足就明确未覆盖。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| R1 | S2 已完成调查后退出；修改有效 ADR 至 cases.md 的恢复版本，再恢复原会话并明确重新调用 brainstorming。A/B 各一次，覆盖已支持的 M/U 两入口 | 读取新版本并复核受影响设计；B 取得新事件/新投递，不能沿用“一次读过”标记 |
| R2 | 同会话第二次调用目标技能；再调用无关技能 | 目标调用重新投递，无关调用不注入；共用规则无无意翻倍注册 |

### 8.3 重复与修订

同一格两次结论不一致，或拟用某格证明 B 的质量增益时，增加该格第 3 对 A/B 独立运行。若差异仍不稳定，结论为证据不足，保留可能解释；不用不断重试挑出胜者。修改 policy、脚本或环境后另建批次，重跑受影响配对和必要回归；旧失败保留，已知缺陷处理到有依据为止。
