# A4 跨机验证：从这里开始

版本 1.0，2026-09-17。**材料已准备；另一台机器的 Claude 实测待执行。**

## 带什么

1. 本方法仓库，或本次移交包（保留内部目录结构）。
2. 本轮的 `explicit-architecture` 只读输入。完整移交包已附 `pilot-inputs/`，涵盖当前项目入口、Wiki、架构文档和订单源码/测试；`SNAPSHOT.json` 记录来源及哈希。它足够做本轮受控设计对照，不是完整可构建仓库。后续真实业务闭环再带完整项目及 A2/A3 记录，保留未提交文件。
3. 目标机器已有 Claude Code 登录及原版 Superpowers。运行时和插件版本在目标机记录，不复制原机凭据或用户设置。

不必携带原机 `.local/` 下的完整日志。这里的 `h1/` 已含诊断器和测试；旧证据摘要见其 README。新方案及本材料使用相对路径；旧研究/路线图中的原机绝对路径仅是历史证据索引，不是新机启动配置。

## 按什么执行

执行唯一方案：[A4 正式验证方案](../../docs/superpowers/plans/2026-09-17-a4-context-validation.md)。先固定环境和输入，再做 H1、最小 B 组实现、语义对照、恢复检查、采用结论。

**现成可运行的部分：** `node --test validation/a4-context/h1/capture-hook.test.mjs`。

**仍需在目标机完成的部分：** 真实双入口协议验证；Task 3 的语义注入脚本与对照配置；全部质量实验。现有 H1 诊断器只返回 marker，不能作为最终注入器。

`cases.md`、`review-guide.md`、本方案和结果模板属于操作者材料，放在被测工作区之外。只把指定业务输入、资料和 `knowledge-policy.md` 的副本交给被测会话。

## 在新机器直接发送给执行 Agent

```text
请继续本仓库 docs/superpowers/plans/2026-09-17-a4-context-validation.md。
这是操作者会话，先读 validation/a4-context/README.md、正式方案和路线图当前状态。
Claude Code 已在这台机器安装并登录；请核对实际连接、版本、原版 Superpowers 和试点材料，然后从第一个未完成检查点执行。
按方案分开操作者、被测会话与评审材料，只比较“项目规则”与“项目规则＋阶段 Hook”。
复用已有 H1 诊断器；B 组语义注入器尚未实现，按 Task 3 在隔离环境完成后再运行对照。
保持原版 Superpowers 和正式项目材料；质量优先，证据不足可以得出平局或未完成。
不要重做 A3 的 OpenSpec / Spec Kit 比较，也不要把本轮完成写成整个 A4 完成。
遇到本机无法自动完成的真实交互斜杠输入时，给我该次准确命令及预期证据，继续其他独立准备。
```

使用完整移交包时，操作者先把包根的 `pilot-inputs/` 作为本轮资料源；实际被测工作区仍按方案另建。若另用当前项目，记录新的起点并核对用例前提，不混合两个版本；不复用原机绝对路径。

## 结果放哪里

按正式方案在独立 `a4-evaluation/results/` 保存；模板在 [templates](templates/)。只把汇总结论及可移交的脱敏证据回写项目记录，原始日志留目标机。最终状态回到[行动路线图](../../docs/roadmap/action-roadmap.md#a4)。
