# 统一提示与答复卡（操作者使用）

本文件不放入被测仓库。正文不包含期望设计答案、ADR 文件名或组别。每次实际输入及答复逐字保留在 run 记录。

## H1：只测协议，不计语义质量

模型调用入口 M：

```text
请通过 Skill 工具调用 superpowers:brainstorming。本次只做入口诊断，不做业务设计、不读取项目资料。
技能加载后，若上下文出现 H1_PROTOCOL_PROBE，请原样回显其中的标记；没有就明确说未见标记，不猜测。
```

手动入口 U：在 Claude Code 的真实交互输入框直接输入下面这一行，不通过普通提示让模型转述它。

```text
/superpowers:brainstorming 本次只做入口诊断，不做业务设计、不读取项目资料。若上下文出现 H1_PROTOCOL_PROBE，请原样回显其中的标记；没有就明确说未见标记，不猜测。
```

负例：M 要求实际调用 `superpowers:verification-before-completion`；U 直接输入 `/superpowers:verification-before-completion`，说明本轮仅检查命令入口、不声明业务完成。负例不要求模型重复历史标记；检查是否产生新的注入。

## 主比较业务正文（所有用例共用）

```text
请基于本项目的 Intent.md，设计“订单定价的币种一致性校验”这个小变更。
本轮只做 brainstorming，范围止于可审阅的设计草稿及必要澄清；草稿直接写在对话中。
保留现有折扣行为，不实施业务代码、不提交、不发起 MR。
```

- M：在上述正文前加“请通过 Skill 工具调用 superpowers:brainstorming 来处理以下任务。”
- U：把 `/superpowers:brainstorming ` 和业务正文作为一次真实手动命令输入。
- 不额外写“记得读 Wiki/ADR”。这项要求只来自两组共用 policy，B 的额外投递是受测因素。

## 澄清答复卡

| 问题 | 统一答复 |
| --- | --- |
| 要不要实现/提交？ | 本轮只要对话中的设计草稿，不实现、不提交。 |
| 范围是什么？ | 以 Intent.md 已确认范围为准；保持既有折扣规则，不引入汇率转换。 |
| 工程负责人是谁？ | 我是本次工程负责人。请先完成有依据的设计，明确仍需我接受的关键决定。 |
| 工具不可用怎么办？ | 使用本会话已有搜索和文件读取工具，缺少的能力如实记录。 |
| 找不到关键原文，是否允许猜测？ | 当前没有额外原文可补充；请说明缺口影响与可安全确定的部分，保留需要确认的决定。 |
| 要不要跳过原版设计步骤？ | 按原版方法进行；本轮交付边界是设计草稿，先完成必要澄清。 |

其他问题按真实输入回答并记录；如果答案引入新的业务或工程信息，同步两组并重做受影响配对。操作者不逐组暗示评分答案，不代替生成者补齐遗漏。

## R1：恢复后重新调用

业务正文统一为：

```text
上游架构资料已经修订。请继续同一项币种一致性校验的设计，重新核对适用资料，复核受影响部分，并在对话中给出更新后的草稿和变化说明。
```

M/U 仍按各自真实入口启动。R6 的“只恢复、不重新调用”单独观察，不能冒充 R1。
